What's new in the APS workbenchAPS 工作台新功能

Ask questions in plain language, compare what-if scenarios before touching the plan, see why an order is late, and let the workbench turn rejections and shift notes into next steps. Nothing changes the approved plan until you approve a proposal.用自然语言提问，在改动排程前比较假设场景，查看订单延误的原因，并让工作台把驳回意见和交接班记录转化为下一步操作。在您批准方案之前，已批准的排程不会被改动。

Start from the project root:在项目根目录启动： ./run.sh start, then open然后打开 http://127.0.0.1:8100/aps/ planning alone:单独运行排程： ./run.sh start aps → :8095 · ./run.sh help lists every command列出全部命令 The first plan takes about a minute. The首次排程约需一分钟。右上角 EN 中文 switch sets the language.按钮切换语言。

A 3-minute tour三分钟上手

  1. In the command bar, ask在计划助手中输入 What if LKT-04 goes down for 8 hours?如果 LKT-04 停机 8 小时会怎样？ and press并点击 Ask提问.
  2. When the scenario appears, click场景出现后，点击 View查看 to see it on the Gantt, then在甘特图中查看，然后点击 Make proposal转为方案.
  3. Enter your name, type输入姓名，在驳回框中写 Too many changes改动太多了 in the box under the buttons and click，然后点击 Reject驳回.
  4. In在 After the rejection驳回之后, click中点击 Re-run moving only the disrupted machine and order重新求解，只调整受影响的设备和订单.
  5. In在 Shift notes交接班记录, click the note中点击记录 CNC-03 液压系统故障，已停机。 — CNC-03 gets a— CNC-03 在甘特图上出现 ⚠ on the Gantt.标记。

What the reading shows识别结果包含

Two readings两次识别Laya reads the event kind twice, in two different wordings, and shows whether they agree.Laya 用两种不同措辞识别事件类型，并显示两者是否一致。
Guard防护“guard: clean” or “guard: prompt injection”. A flagged message never applies itself; check the sender.“防护：正常”或“防护：提示注入”。被标记的消息不会自动应用，请核实发件人。
Cue words信号词e.g. “customer's line would stop → priority 3”, with the words that triggered it.例如“客户会停线 → 优先级 3”，并显示触发的词语。
Why you confirm为何需确认Readings disagree · below the confidence gate · facts missing · the sender is unsure · flagged by the guard. With none of these, the event is safe to apply.识别不一致 · 低于置信度阈值 · 缺少信息 · 发件人不确定 · 被防护模型标记。若都没有，事件可直接应用。

If the sender sounds unsure — “might”, “not confirmed”, “可能”, “eventuell” — the main button becomes若发件人语气不确定——“might”“not confirmed”“可能”“eventuell”——主按钮会变为 Run as what-if作为假设运行: see the effect first, act when it is confirmed.：先看影响，确认后再执行。

Proposal panel方案面板

Reject a proposal with a comment驳回方案并填写原因 Laya

Enter your name, type why in the box under the buttons (optional), and click输入姓名，在按钮下方的框中写明原因（可选），然后点击 Reject驳回. Laya reads the reason, andLaya 会识别原因， After the rejection驳回之后 highlights the matching next step:面板会突出对应的下一步：

Too many changes改动太多Re-run moving only the disrupted machine and order重新求解，只调整受影响的设备和订单
Everything else keeps its machine and sequence. Much faster (1.2 s vs 18 s in our test), same on-time result.其他工序保持原设备和顺序。速度更快（测试中 1.2 秒对 18 秒），准时结果相同。
A customer promise breaks违背客户承诺Tick the orders to protect (those the proposal made late are pre-ticked, or the order named in your comment), then勾选要保护的订单（方案导致延误的订单或意见中提到的订单已预选），然后点击 Re-run protecting these orders重新求解并保护这些订单. They get priority 3.。这些订单将获得优先级 3。
People or tools missing人员或工装不足Block the machine while people or tools are missing在缺人或缺工装期间封锁该设备 opens a maintenance form for that machine; fill in when and how long.打开该设备的保养表单，填写开始时间和时长。
The event was wrong事件有误Correct the event修正该事件 opens the original event to fix and resubmit.打开原事件，修正后重新提交。

All four steps stay on screen, because Laya's reason is sometimes wrong. When it is unsure, nothing is highlighted and you pick. The四个选项始终显示，因为 Laya 的判断有时会出错。不确定时不会突出任何选项，由您选择。 Versions and events版本与事件 panel counts the reasons over time.面板会统计历次驳回原因。

If Laya reads a likely breakdown, the note shows若 Laya 判断可能故障，记录会显示 ⚠ likely breakdown⚠ 可能故障, the machine gets a，该设备在甘特图上出现 ⚠ on the Gantt, and标记，并可点击 Report machine down上报设备停机 opens a machine-down event — fill in the hours.打开停机事件——填写小时数即可。

Under each note,每条记录下方有 Actually:实际情况： OK正常 Watch需关注 Stop停机 records what the machine's condition really was. Laya learns from it (see Training labels).按钮，用于记录设备的真实状态，Laya 会从中学习（见“训练标签”）。

It catches breakdowns but mostly misses early warnings (“vibration still within limits”). A note without a flag does not mean the machine is fine.它能发现故障，但大多识别不出早期征兆（如“振动仍在范围内”）。没有标记不代表设备正常。

Priorities优先级 Rules规则

Priority 3 counts most in the on-time objective, 1 least.优先级 3 在准时交付目标中权重最高，1 最低。

Priority changed优先级变更A new event kind: pick the order and a priority from 1 to 3.新的事件类型：选择订单和 1–3 的优先级。
Priority (1–3)优先级（1–3）An optional field on rush orders, due-date changes, quantity changes, late material and quality holds — changed in the same repair.插单、交期变更、数量变更、物料延迟和质量冻结上的可选字段——在同一次修复中生效。
From the message来自消息内容“Their line stops”, “penalty”, “停线”, “Vertragsstrafe” → priority 3 is filled in. “No rush”, “不急”, “keine Eile” → a rush order gets priority 1. You can always change it.“Their line stops”“penalty”“停线”“Vertragsstrafe” → 自动填入优先级 3。“No rush”“不急”“keine Eile” → 插单优先级为 1。您随时可以修改。

Raising a priority cannot fix an order that is late for another reason — for example, material that arrives late.提高优先级无法解决其他原因造成的延误——例如物料晚到。
